## What the apps do behind the scenes

Every chat app, copilot, and agent:

1. Builds a **request**: instructions, messages, files, tools
2. Sends it to a model through an **API**
3. Gets a **response**
4. Does something with it

Companies build products on that loop.

---

## Chat app vs API

| | Chat app | API |
|---|---|---|
| Used by | A person | A program |
| System prompt | The vendor's, hidden | **Yours** |
| Memory, projects | Built in | Only if you build them |
| Payment | Subscription | Per token |

Same model. The app is a product built on the API.

---

## Anatomy of an API call

```json
{
  "model": "claude-sonnet-...",
  "system": "You are a concise tutor.",
  "messages": [
    {"role": "user", "content": "Explain recursion."}
  ],
  "max_tokens": 500,
  "temperature": 0.7
}
```


---

## The pieces

| Part | What it does |
|---|---|
| **model** | Which model answers |
| **system** | Standing instructions |
| **messages** | The conversation so far |
| **max_tokens** | Cap on response length |
| **temperature** | How much randomness (week 1's sampling) |

---

## What comes back

```json
{
  "content": [{"type": "text", "text": "Recursion is..."}],
  "stop_reason": "end_turn",
  "usage": {"input_tokens": 31, "output_tokens": 74}
}
```

- **content**: the reply
- **stop_reason**: finished, hit the limit, or wants a tool
- **usage**: what you're billed for

---

## The model remembers nothing

- Each call is **independent**
- A "conversation" = you resend the whole history every time
- That's why long chats cost more and degrade
