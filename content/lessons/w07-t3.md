## Plugins

A skill is one procedure in one folder. Real work usually needs several things together: a few related skills, a connection to the system where the data lives, and some settings. A **plugin** bundles several pieces into one package that can be installed and shared.

| A plugin can contain | What it adds |
|---|---|
| **Skills** | Procedures the agent can follow |
| **Connectors** | Links to outside systems, such as a calendar or a database (next week's topic) |
| **Commands** | Shortcuts you can call by name |
| **Other components** | Settings and helpers, depending on the product |

Organizations use plugins to package "the way we do things here": a set of skills for the sales team's proposals, connected to the customer database, installed by everyone on the team at once. Three reasons this matters to an organization:

- **Consistency.** Everyone's agent follows the same procedure and uses the same template, so a proposal looks the same whoever prepared it.
- **Onboarding.** A new employee installs the plugin and their agent knows the team's procedures on the first day.
- **Updating.** When the procedure changes, the plugin is updated once and everyone gets the new version.

Plugins are shared through **marketplaces**, which are catalogs you can browse and install from. Vendors run public ones, and an organization can run a private one for its own staff.

### Read before you install

A skill is a set of instructions that an agent will follow with your files and your permissions. That makes installing one closer to installing software than to reading a document. A poorly written or malicious skill can tell an agent to delete files, send data to an outside address, or run a script you didn't expect. Before you install a skill or plugin:

- **Consider the source.** A plugin from the vendor or from your own organization deserves more trust than one from an unknown author.
- **Read the `SKILL.md`.** It's plain Markdown. Does it do what its description says, and only that?
- **Look at the supporting files**, especially scripts. If a skill includes code you can't read, ask a model to explain what the script does before you run it.
- **Check what it connects to.** A plugin with connectors reaches outside your computer.
- **Try it on a copy** first, with approvals on.

The same care applies in the other direction. Before you share a skill, check that it contains no personal details, passwords, or file paths that reveal more than you intend.

## Skills in chat vs skills in an agent

Skills also work in a regular Claude chat. But they're more limited there, because a chat has no working folder.

| In chat | In an agent working in a folder |
|---|---|
| Works on uploaded **copies** of your files | Works on the **real files** |
| Standing instructions are typed into a settings field | An instruction file **lives with the work** |
| Can't run your project's tests or local tools | Can run scripts, tests, and local tools |
| You download the results | Results are saved in place |

So "skills work in chat" is true, and "skills work best in an agent with a folder" is also true. The accurate summary is that skills are **limited** in chat, not absent.

### Where to run a skill

Take the weekly-status skill from the last topic. In an agent pointed at your notes folder, it reads the week's notes itself and saves the update to `status/`. In a chat, you would upload the notes, the skill would produce the update, and you would download it and file it yourself. The procedure is the same. The fetching and the filing fall to you.

| The task | Better place |
|---|---|
| Turns one pasted or uploaded item into another, such as notes into flashcards | Chat is fine |
| Reads or writes many files | An agent with the folder |
| Needs to follow the folder's conventions | An agent, where the instruction file is read |
| Runs a script or a test | An agent |
| You're on your phone, away from your computer | Chat |

When you write a skill, decide where it will run and write for that place. A skill that says "read every file in `notes/`" has nothing to read in a chat.

## Key terms

**Plugin**: a package bundling skills, connectors, and other components for sharing. **Marketplace**: a catalog from which plugins and skills can be installed. **Working folder**: the folder an agent has been given to read and change.
