This course teaches you to use modern AI tools for real professional work: research, writing, analysis, coding, communication, and automating routine tasks. You will use these tools every week. No prior coding experience is assumed. Some weeks involve software, but you will direct an AI to write the code; what you are learning is how to specify the work and check it.

## 2. What a large language model is

The AI systems in this course are built on **large language models**, or LLMs. Understanding roughly how they work will help you predict where they succeed and where they fail.

### A next-token predictor

An LLM reads and writes text as **tokens**, which are pieces of words. In English a token is about three-quarters of a word on average. Given the text so far, the model calculates a probability for every possible next token, picks one, adds it to the text, and repeats. A full answer is thousands of these predictions in a row.

If you give a model "The capital of France is", the token "Paris" is very likely, and the model will almost always produce it. For an open question with many reasonable answers, the probabilities are spread out, and the model's choice could go many ways.

This is a simple mechanism with surprising results. To predict text well across a huge range of subjects, a model has to absorb a great deal about language, facts, reasoning patterns, and how people explain things. But it is important to remember what it is doing: producing **plausible** continuations. Plausible usually coincides with true. Not always.

### Trained in two stages

Models are built in two main stages.

1. **Pretraining.** The model learns to predict the next token across an enormous amount of text. The result has broad knowledge and fluent language, but it is not yet a helpful assistant; given a question, it might continue with more questions.
2. **Tuning into an assistant.** Further training, using examples and feedback, teaches the model to follow instructions, answer helpfully, take on an assistant's manner, and decline some requests.

### The knowledge cutoff

Pretraining data stops at some date, called the **knowledge cutoff**. The model knows nothing about events after it unless a tool provides the information: a web search, a file you upload, or a connection to another service. When you ask about anything recent, ask yourself whether the tool you're using actually looked it up or is answering from what it learned during training.

### Why answers vary

Models don't always choose the single most likely token. They **sample** from the probabilities, which makes their writing more natural and varied. The consequence is that the same prompt can produce different answers on different runs: different wording, different structure, and sometimes different facts.

### What this means for you

Fluency is not accuracy, and confidence is not accuracy. A model sounds just as sure when it is wrong. Unless it has a tool, it does not look anything up. Your role, throughout this course, is to decide what to ask, describe it well, and check what comes back.

## 3. The surfaces map

The same model can behave very differently depending on how you reach it. A **surface** is the way you interact with an AI and, just as important, what it can see and change. A model in a chat window can only see what you paste in. The same model working as an agent on your computer can read every file in a folder, run code, and save its work. The surface often matters more than which model is underneath.

This course uses eight surfaces:

| ID | Surface | What it is | Example |
|---|---|---|---|
| S1 | Chat assistant | A conversation in a browser or app | Claude, ChatGPT, Copilot Chat |
| S2 | Embedded copilot | AI inside an application you already use | Copilot in Outlook |
| S3 | Coding assistant | AI inside a development environment, with access to code, terminal, and tests | Claude Code in VS Code |
| S4 | Local agent | AI that works directly on the files and folders on your computer | Claude Cowork |

The course walks this map in order. Weeks 1–5 are mostly chat. Weeks 6–8 cover local agents and the surfaces that build on them. Weeks 9–10 are coding assistants. Weeks 11–12 build small programs on an API. Week 13 is always-on agents. Weeks 14–15 look at organizations and bring everything together in your capstone.

## 4. The 4D framework: Delegation first

Throughout the course we use the four skills of AI fluency from Anthropic's *AI Fluency* course:

- **Delegation**: deciding what to hand to AI at all.
- **Description**: communicating the task clearly.
- **Discernment**: judging what comes back.
- **Diligence**: taking responsibility for the result.

Each week emphasizes one. This week is **Delegation**, because it comes first: before you open a chat, decide whether this is a job for AI. Four questions help:

1. Is this a task AI does well (drafting, summarizing, restructuring, explaining, generating options)?
2. What would a wrong answer cost?
3. Can I check the result?
4. Would anyone else's data be involved?

If the answer to question 3 is "no" and the cost in question 2 is high, think hard before delegating.

## Key terms

**Token**: a piece of a word; the unit models read, write, and are billed in. **LLM**: large language model. **Knowledge cutoff**: the date after which a model's training data stops. **Sampling**: choosing the next token from a probability distribution rather than always the top choice. **Surface**: how you reach an AI and what it can see and change. **4D framework**: Delegation, Description, Discernment, Diligence.
